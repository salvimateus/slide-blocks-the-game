# Primitives

- One inventory for the whole project, at the project root.
- The project uses no `class_name`: each name below is the `preload` constant or the autoload name that the code uses, or the file name of a tool script.
- Status is `confirmed` (implementation read) or `inferred` (only references seen); `pending <branch>` marks code that the integration branch `main` does not have yet, and a bare `pending` marks code that is not in a commit yet.

## core

- **`Level`**, `scripts/core/level.gd`, confirmed
  The parsed map of one level as flat arrays by cell, shared by the rules, the solver and the views. Contract: `id`, `index`, `name_key`, `hint_key`, `cols`, `rows`, `cells`; by cell `floor_cells`, `obstacle`, `deflector` (`NONE`, `NW`, `NE`, `SW`, `SE`) and `floor_bit` (paint bit, -1 off the floor); `starts` (start cell of each block, index = block id - 1), `floor_count`, `step` (cell offset for U, D, L, R), `errors`, `is_valid()`, `col_of(cell)`, `row_of(cell)`. The level definitions live in `scripts/core/levels_data.gd` (`LEVELS`); `name_key` and `hint_key` are keys of [[PRIMITIVES#Strings]].
  Consumers: >=7 (LevelParser, SlideRules, Solver, Session and level_thumb preload it; BoardView and SwipePlayer read its fields).
- **`LevelParser`**, `scripts/core/level_parser.gd`, confirmed
  Turns one map definition (rows of glyphs) into a validated Level. Contract: `static parse(def: Dictionary, index: int) -> Level`; it never fails hard, each problem goes to `Level.errors` as `row R col C: message`, counted from 1. Glyphs: `#` void, `X` obstacle, `.` floor, `1` to `9` block start on floor, `┌┐└┘` deflectors NW, NE, SW, SE on floor. It rejects floor on the border, a floor that is not connected, a deflector with floor on a closed side or no floor on an open side, a block on a deflector, and block ids that are not 1..n. The limits `MAX_FLOOR` 62, `MAX_CELLS` 255 and `MAX_BLOCKS` 4 come from the state packing of [[PRIMITIVES#Solver]]; raise them only with a Solver change.
  Consumers: >=6 (Game, board_lab, ui_lab, demo_board, level_thumb, tools/levels_tool.gd).
- **`SlideRules`**, `scripts/core/slide_rules.gd`, confirmed
  The one movement rule: all blocks slide in one direction, one cell for each tick, until each block stops. Contract: directions `UP` 0, `DOWN` 1, `LEFT` 2, `RIGHT` 3, `DIR_CHARS` "UDLR", `dir_from_char(c)`; `static resolve(level, pos, dir, out, events = null) -> int` writes the end cells to `out` and returns the mask of the floor bits that the blocks entered (the start cells are not in it); with an `events` Array it appends `step` events (`tick`, `block`, `from`, `to`, `dir`, `turned`) and `stop` events (`tick`, `block`, `cell`, `dir`, `cause` wall, block or loop, `travelled`) in tick order. A block on a deflector cell turns before its next step; when two blocks aim at one cell, the lower block id moves; a repeat of (block, cell, dir) stops the block with cause `loop`. SwipeInput, BoardView, BlockView, FxPool and Harness use the same direction order.
  Consumers: >=4 (Session, Solver, demo_board, board_lab); SwipePlayer reads its events through the Session outcome.
- **`Solver`**, `scripts/core/solver.gd`, confirmed
  Exact breadth-first search for the minimum move count of a level. Contract: `static solve(level, cap = 3000000) -> {min, solution, states}` (`solution` is a string of `SlideRules.DIR_CHARS` letters), or `{}` when the level has no solution or the search passes the cap; `static has_dead_end(level)` (a reachable position set that cannot return to the start); `static has_loop(level)` (a lone block on a deflector hits the loop guard); `static pack(pos) -> int` (8 bits for each block). A move counts only when the end positions differ from the start positions, the same rule as Session. The levels of `levels_data.gd` never solve at runtime: their pars come from [[PRIMITIVES#ParData]], so a level change needs a new par write. The one runtime solve is [[PRIMITIVES#RandomLevel]], on a worker thread and with its own state cap.
  Consumers: 3 (tools/levels_tool.gd, SoloSearch, RandomLevel).
- **`SoloSearch`**, `tools/solo_search.gd`, confirmed
  Offline search of the one-block version of a level with two or more blocks. Contract: `static search(def, index) -> {keep, walls, min, solution, states, floor, searched, dead_end}`, or `{}` when no version passes. For each kept block it tries 0 to `SEARCHED_WALLS` searched walls (the removed start cells first), then turns each floor cell that the lone block cannot enter into a wall; all walls stay within `MAX_WALL_SHARE` of the floor, and a version needs `MIN_MOVES` or more and no loop. A version with a dead end passes only in a last tier, when no candidate of the map is free of one (`dead_end` true). Among the versions with the fewest walls it picks the most walls on removed start cells, then the highest minimum.
  Consumers: 1 (tools/levels_tool.gd).
- **`ParData`**, `scripts/core/par_data.gd`, confirmed
  The generated par table of each level version, so the game never solves a level of `levels_data.gd` at runtime. Contract: `PAR[id] = {min, solution}` for each level id and `demo`; `SOLO[id] = {keep, walls, min, solution}` for a level with two or more blocks that has a one-block version (`keep` is the kept block id of the normal map, `walls` the new obstacle cells as ascending `y * cols + x` indices of the normal map). A level with no `SOLO` entry has no one-jujuba option. Only [[PRIMITIVES#levels_tool]] writes the file.
  Consumers: 6 (Game, LevelModes, demo_board, board_lab, ui_lab, tools/levels_tool.gd).
- **`SoloVariant`**, `scripts/core/solo_variant.gd`, confirmed
  Builds the one-block map definition of a level. Contract: `SUFFIX` "_solo"; `static make_def(def, keep, walls) -> Dictionary`: block `keep` becomes block 1, the other block glyphs become floor, each `walls` cell (`y * cols + x`) becomes `X`, the id gets `SUFFIX` and the hint key is "". It does not read ParData, so tools/levels_tool.gd can load it before the first par write; keep it free of that import.
  Consumers: 4 (LevelModes, Save, SoloSearch, tools/levels_tool.gd).
- **`LevelModes`**, `scripts/core/level_modes.gd`, confirmed
  The playable versions of each level of `levels_data.gd`: the normal map and, when [[PRIMITIVES#ParData]] has a `SOLO` entry, the one-block map. Contract: static `solo_state(index) -> &"ready" | &"single" | &"none"` (`single`: the map has one block), `def_for(index, solo)`, `par_for(level_id) -> {min, solution}` or `{}` (for `l4` or `l4_solo`), `record_id(index, solo)`, `is_level_id(level_id)`, `info(index, solo)` (the `info` of `Bus.level_loaded`: `mode`, `index`, `seed`, `solo`, `name_key`, `hint_key`). The one-block version applies only when `solo` is true and the level has a `SOLO` entry, else each call gives the normal version, so the `solo` setting alone never decides the mode. A one-block version has no hint.
  Consumers: 6 (Game, Save, hud, level_card, level_select_screen, ui_lab).
- **`RandomLevel`**, `scripts/core/random_level.gd`, confirmed
  The deterministic random level generator: one seed gives the same map, minimum and solution on each device. Contract: `static generate(seed, solo, cancel: Cancel = null) -> {level, def, min, solution, states, attempts, blocks, deflectors, seed, solo}`, `{"cancelled": true}` after `Cancel.cancelled`, or `{}` when no attempt passes; `SEED_MIN`, `SEED_MAX`, `SCORE_INDEX` (the level index to give to `ScoreRules.thresholds`), `LEVEL_ID` "random", `STATE_CAP`. A candidate must be valid, have `FLOOR_MIN` floor cells or more, no loop, a minimum from `MIN_MOVES` to `MAX_MOVES`, `MIN_STATES` states or more and no dead end; after `MAX_ATTEMPTS` with the picked block count it tries as many with one block. It is pure (no node, no autoload, no static state), so it runs on a worker thread. Each limit is a count, never a time, so a time limit breaks the same level on each device; a change of this file changes the level of each seed. `tools/random_tool.gd` checks a seed range for a level, determinism, the thread result and the cancel, and prints `RANDOM_OK <n>`.
  Consumers: 2 (Game on a worker thread, tools/random_tool.gd).
- **`ScoreRules`**, `scripts/core/score_rules.gd`, confirmed
  The star ranges, the move limit and the tension point of a level, from its minimum move count. Contract: `static thresholds(min_moves, index) -> {min, three_max, two_max, limit, tension_moves}`, `static stars_for(moves, t) -> 0..3`, `static range_for(stars, t) -> Vector2i(lo, hi)` (stars 0 gives the moves above the limit), `static is_tense(moves_used, t)`. The limit factor becomes smaller as the level index increases, so each caller must give the real level index.
  Consumers: >=4 (Session, Game, ui_lab, tools/levels_tool.gd); RangeBar reads the thresholds dictionary.
- **`Session`**, `scripts/core/session.gd`, confirmed
  The rule state of one level attempt: positions, paint, moves, status and tension. Contract: `Session.new(level, min_moves, hues)` with `min_moves` from [[PRIMITIVES#ParData]] or a runtime solve and `hues` from [[PRIMITIVES#Palette]]; `history` (one `SlideRules.DIR_CHARS` letter for each counted swipe, in play order); `swipe(dir) -> outcome` with `ignored`, `dir`, `moved`, `counted`, `events`, `paints` (`tick`, `block`, `cell`, `hue`, `fresh`), `positions`, `ticks`, `status`, `moves_used`, `stars`, `tense`, `tense_changed`, `tier_dropped`, `last_cell`; `snapshot() -> Dictionary`, `is_complete()`, `stars()`; `status` is `ready`, `playing`, `won` or `lost`. The state changes at once in `swipe` and the views replay the outcome after it ([[PRIMITIVES#SwipePlayer]]). A swipe that moves no block does not count, a level complete on the limit move is a win, and a repaint gives the cell the color of the last block.
  Consumers: >=4 (Game, demo_board, board_lab, ReplayRunner); Harness reads `snapshot()` through `Game.snapshot()`.
- **`Palette`**, `scripts/core/palette.gd`, confirmed
  The color source of the game: the colors of the light and the dark theme and the eight block color families. Contract: `THEMES` (`&"light"`, `&"dark"`), the tables `LIGHT` and `DARK`, `static apply(name)` (a name other than `&"dark"` gives light) and `static var theme`; each theme color is a `static var` with the name of its table key, so no `const` expression can use it; `SHADE` and the block family `PAINT`, `BODY` and `OUTLINE`, indexed by palette index 0..7 (`FAMILY_SIZE`), are `const` and the same in both themes; `static pick_block_hues(count, rng) -> PackedInt32Array` of palette indices (a random start k, then k, k+2, k+4, k+6 in a shuffled order, and the odd offsets after four blocks). A node keeps the colors that it reads when it is built, so only [[PRIMITIVES#Game]] calls `apply()`, at boot and in its theme pass, and a new node that holds theme colors and lives across a theme change needs a step in that pass. `INK` is cream in the dark theme, so block eyes and drop shadows use `SHADE`, and the body of a jelly icon uses `JELLY_FACE`, which stays light. The obstacle colors are theme colors here, not BoardTuning knobs. A block `hue` in the code is a palette index, not a degree; `HUES` holds the degrees only as a reference.
  Consumers: >=19 (Game, Harness, Save, board_lab, ui_lab, background, BoardView, ceremonies, demo_board, FxPool, SwipePlayer, TextureBank, Icon, JuicyButton, level_thumb, RangeBar, Screen, switch, UiTheme preload it).

## runtime

- **`Bus`**, `autoload/bus.gd`, confirmed
  The global signal hub between game flow, board, audio, UI and harness. Contract: signals only, declared in `autoload/bus.gd`; each listener connects by itself. Game emits the level flow signals at rule time, directly after `Session.swipe`; [[PRIMITIVES#SwipePlayer]] emits the swipe signals at visual time; `scripts/board/ceremonies.gd` emits the `ceremony_*` signals. Code that must follow the screen (sounds, harness marks) listens to the visual-time signals; code that needs the rule state listens to `session_changed`. Game also emits `level_loaded(index, info)` (the info of [[PRIMITIVES#LevelModes]], or mode `random` with index -1), `level_generated` and the `replay_*` signals, with one `replay_finished` for each `replay_started` on each path; Save emits `setting_changed` and `locale_changed`. Save emits `theme_changed(theme)` when `Save.theme()` changes; Game emits `theme_applied(theme)` when the new theme is on screen, the cover is gone and the reopened screen is at rest.
  Consumers: >=18 (Game, Harness, Music, Save, Sfx, ui_lab, ceremonies, SwipePlayer, defeat_card, hud, JuicyButton, LanguageRow, level_card, level_select_screen, LoadingScreen, pause_dialog, ReplayOverlay, result_card).
- **`Tuning`**, `autoload/tuning.gd`, confirmed
  The home of the tuning knobs: global knobs in the autoload and one constants file for each domain. Contract: constants only; `Tuning.Board`, `Tuning.Audio` and `Tuning.Ui` preload `scripts/board/board_tuning.gd`, `scripts/audio/audio_tuning.gd` and `scripts/ui/ui_tuning.gd`, and most scripts preload these files directly as `BoardTuning`, `AudioTuning` and `UiTuning`. Board knobs are in board units (one atlas texel); BoardView scales them into the fit rect.
  Consumers: autoload >=7 (Feel, Game, BoardView, SwipeInput, card_screen, column, pause_dialog); BoardTuning >=7 (BlockView, BoardView, ceremonies, demo_board, FxPool, SwipePlayer, TextureBank); AudioTuning >=4 (Music, Sfx, AudioBank, ui_lab, which reads `TENSE_BPM`); UiTuning >=8 (Game, ui_lab, column, JuicyButton, RangeBar, Screen, switch, UiTheme).
- **`Feel`**, `autoload/feel.gd`, confirmed
  Hit-stop, haptics and the reduced-motion scale in one place. Contract: `hit_stop(ms)` (lowers `Engine.time_scale` for real milliseconds scaled by `motion()`; a new hit-stop replaces the end time), `set_base_time_scale(scale)` (used by the harness `--time-scale`), `vibrate(kind)` with a key of `Tuning.HAPTIC_MS` (mobile only, with the `haptics` setting), `motion() -> float` (1.0, or `Tuning.REDUCED_MOTION_SCALE` with the `reduced_motion` setting). Change `Engine.time_scale` only through Feel; a tween that must keep real time needs `set_ignore_time_scale(true)`, as in Music. Scale each motion amount and particle count by `motion()`.
  Consumers: >=15 (Harness, BlockView, BoardView, ceremonies, FxPool, SwipePlayer, card_screen, defeat_card, home_screen, hud, JuicyButton, level_select_screen, pause_dialog, Screen, switch).
- **`Game`**, `autoload/game.gd`, confirmed
  The game flow autoload: boot, screens, the level phases, the random level job and the replay. Contract: `boot(host)`, `open_home()`, `open_levels(page = -1)`, `start_level(index)` (the version from the `solo` setting through [[PRIMITIVES#LevelModes]]), `start_random(seed = -1)`, `cancel_random()`, `set_random_hold(ms)` (harness only), `restart()`, `next_level()`, `set_paused(on)`, `request_swipe(dir)`, `skip_ceremony()`, `can_replay()`, `play_replay()`, `stop_replay()`, `current_solution()`, `quit(code)`, `snapshot()`; fields `screen` and `level_index`. The phase is `off`, `intro`, `play`, `ceremony`, `card`, or `replay` while a replay plays over the card; `screen` also takes `replay` and `loading`. `request_swipe` acts only in `play` and holds one swipe while a swipe plays. The random job runs `RandomLevel.generate` on one `Thread` for each job, in a method that reads no member and touches no node, and returns with `call_deferred`; a stale or cancelled result is dropped by its serial, and `quit()` cancels and joins each thread before the app quits. Game is the only game caller of `Save.record` (ui_lab also calls it), and a random level stores no record and opens no level. A change of the `solo` setting in the pause dialog starts the level again in the new mode when the play goes on. A replay starts only from `card` with a non-empty `Session.history`, through [[PRIMITIVES#ReplayRunner]], and the card returns with `CardScreen.reopen()`. `button_rect(button) -> Rect2` gives a named button in base units of the viewport for a scripted tap, or an empty rect when it is not on screen; the names are in the function. Game applies `Save.theme()` to [[PRIMITIVES#Palette]] at boot, before it builds the Theme. After boot, on `Bus.theme_changed`, its theme pass fades in a cover in the old colors, applies the theme, builds again the Theme, the [[PRIMITIVES#UiBake]] and [[PRIMITIVES#TextureBank]] looks, the background, the trays and all screens, opens the same screen in the same state, lifts the cover and emits `Bus.theme_applied`; a change during the pass starts one more pass. During the pass, keys and `request_swipe` do nothing, and the random job result and the replay end wait for it. `_make_screens()` makes all screens and connects their signals, so a new screen or screen signal goes there or a theme change loses it; the new screens exist before the old ones are freed, so a call during the pass always finds a live screen.
  Consumers: >=9 (Harness, main, board_lab, home_screen, hud, level_select_screen, pause_dialog, result_card, defeat_card).

## board view

- **`TextureBank`**, `scripts/board/texture_bank.gd`, confirmed
  Bakes every board visual into one atlas texture and serves its regions. Contract: add an instance to the tree and `await bank.bake()` (signal `baked`; Game.boot does it before it makes a view; it does nothing when the atlas is already baked), `await bank.rebake()` after a Palette theme change (it draws again into the same textures, so each node, region and emitter that holds one shows the new colors with no change), then the static getters `tex(key)`, `paint_tile(hue)`, `block(hue)`, `particle(key)`, `glitter(hue)`, `pattern()`, `soft()`, `is_baked()`. The region names are in `BIG_ROW_0`, `BIG_ROW_1` and `SMALL_NAMES`, and the inner `Painter` draws them. CPUParticles2D cannot draw an atlas region, so a particle texture must also be in `STANDALONE` and be read with `particle()`. A headless run stores a white placeholder atlas.
  Consumers: >=6 (Game, board_lab, background, BlockView, BoardView, FxPool).
- **`FxPool`**, `scripts/board/fx_pool.gd`, confirmed
  Pooled one-shot CPUParticles2D emitters of one board, so an effect never allocates during play. Contract: `attach(under, over, glow)` one time (BoardView.build calls it); `splash(pos, dir, color, tiles)`, `impact_ring(pos, color, power)`, `rail_spark(pos)`, `ring_glitter(points, hue) -> count`, `burst(center, hues)`, `streak(block)`, `streak_on(block, on)`, `set_streak_color(block, color)`, `set_board_scale(s)`, `clear()`; static `set_particles_enabled(on)` and `set_glow_enabled(on)` act on every pool. Counts scale with `Feel.motion()`. It holds one streak for each block up to `MAX_BLOCKS` 4, the same limit as `LevelParser.MAX_BLOCKS`.
  Consumers: >=4 (BoardView owns it; Game uses the static switches for the PerfPanel options; SwipePlayer and ceremonies call it through `board.fx`).
- **`BlockView`**, `scripts/board/block_view.gd`, confirmed
  One jelly block on screen (shadow, body, eyes), with every block motion as native tweens. Contract: `setup(hue, seed)`, `set_hue(hue)`, `set_mood(&"open" | &"happy" | &"sad")`, `look(dir)`, `start_motion(dir)`, `turn_motion(new_dir, time)`, `squash(dir, amount)` (the jelly squash with the contact edge fixed on the wall), `jiggle(dir, power)`, `nudge(dir)`, `squint()`, `hop(height, time, delay)`, `drop_in(height, time, delay, on_land)`, `hop_to(target, time, delay, new_hue, on_land)`, `deflate()`, `deflate_now()`, `flash_white()`, `reset_pose()`, `settle()`; fields `hue` and `mood`. Its `position` is the cell center and belongs to the caller; the inner nodes (bob, jelly pivot) carry the juice, so a squash or a hop never moves the cell position.
  Consumers: >=3 (BoardView makes it; SwipePlayer and ceremonies drive it through `board.blocks`).
- **`BoardView`**, `scripts/board/board_view.gd`, confirmed
  The node that draws one level (tray, tiles, rails, obstacles, blocks) with the board juice, reused for every level. Contract: `build(level, hues)` after the TextureBank bake, `refresh_theme()` (draws the tray and the scrim again in the current Palette colors and keeps the board state; the tiles, rails, obstacles and blocks change only through `TextureBank.rebake()`), `fit(rect)`, `content_size()`, `cell_pos(cell)` (board units), `cell_global(cell)`, `board_rect_global()`, `floor_cells()`; tile calls `set_tile_paint`, `paint_tile(cell, hue, fresh)`, `tile_flash`, `tile_jump`, `tile_crossfade`, `tile_pulse`, `rail_pop`; `kick(dir, tiles)`, `pulse()`, `nudge(dir)`, `show_scrim(on)`, `set_scrim_now(on)`, `settle()`; `play_intro()` (signal `intro_finished`), `play_restart(hues)` (signal `restart_finished`), `reset(hues)`; `rings_from(cell)`, `rings_from_edge()`, `ring_points(ring)`; fields `level`, `hues`, `paint_hue` (-1 none, `GRAY` -2, else a palette index), `blocks`, `player` (SwipePlayer), `ceremonies`, `fx` (FxPool). `paint_hue` follows the playback, not Session, so during a swipe it can be behind the rule state.
  Consumers: >=3 (Game, demo_board, board_lab); SwipePlayer and `scripts/board/ceremonies.gd` drive it through their `board` field.
- **`SwipePlayer`**, `scripts/board/swipe_player.gd`, confirmed
  Replays one Session outcome on its BoardView and emits the swipe Bus signals at visual time. Contract: `play(outcome)` (a moved outcome slides the blocks; `moved` false plays the nudge and emits `swipe_ignored`), `stop()` (ends at the final state with no signal), `duration(outcome)`, `is_playing()`, `speed_scale` (Game sets `BoardTuning.BUFFERED_SPEED` while a swipe waits in the buffer), signal `finished(outcome)` (also for an ignored outcome); `emit_bus` and `use_feel` are false for the demo board. One tick lasts `BoardTuning.STEP_TIME`, a tile gets its paint at `PAINT_AT` of its tick, and a step into and out of a deflector plays as one arc. It is the only source of `swipe_started`, `tile_painted` (step = tick - 1), `block_turned`, `block_stopped` (power from the travelled tiles), `swipe_finished` and `swipe_ignored`.
  Consumers: >=4 (BoardView owns it as `player`; Game, demo_board and board_lab call `play`).
- **`ReplayRunner`**, `scripts/board/replay_runner.gd`, confirmed
  Plays a stored move list on the main board from the start state. Contract: `setup(board)` one time; `play(level, hues, min_moves, moves)` (moves as `SlideRules.DIR_CHARS` letters) rewinds with `BoardView.play_restart(hues)`, then plays each move of a new Session through `board.player`; `stop()` ends where it is; `is_running()`; signals `stepped(n, total)` (n is 0 at the start state) and `finished(completed, positions, painted)`. The gap between moves is `BoardTuning.REPLAY_MOVE_GAP` and the end hold `REPLAY_END_HOLD`, as real-time timers, and `player.use_feel` is false during the replay, so Feel never slows it. It emits no Bus signal itself, but the SwipePlayer still emits the swipe signals, so the board sounds and the harness marks fire; Game sends the `replay_*` Bus signals.
  Consumers: 1 (Game).

## audio

- **`AudioBank`**, `scripts/audio/audio_bank.gd`, confirmed
  The table of every audio stream, the shared stream cache and the bus layout. Contract: tables `SFX` (key to `path`, `base_hz`, `db`) and `MUSIC` (key to `path`, `bpm`, `bars`, `frames`); `SFX_BUS`, `MUSIC_BUS`; static `ensure_buses()` (SFX and Music buses, master hard limiter, Music low-pass filter; safe to call again), `load_table(table)`, `stream(key)`, `volume_db(key)`, `missing()`, `loop_seconds(clip)`, `is_dummy_driver()`, `music_filter()`. A stream loads only when `ResourceLoader.exists()` is true, so a file that is not baked goes to `missing()` and causes no error. `MUSIC[clip].frames` must equal the loop length that `tools/bake_audio.gd` writes from `tools/audio/score.gd`; the tempo and the bar count are also in `AudioTuning` and in the score, and the loop length is also in `LOOP_SECONDS` of `bake_audio.gd`; `bake_audio -- --check` compares the files only with the score and `LOOP_SECONDS`, so change all four together. The bake sets each music clip to the weighted RMS `level` of its score (after a high-pass at `WEIGHT_HIGHPASS_HZ`) under a soft ceiling, and peak-normalizes each effect, so a music loudness change is a score `level` change. The master limiter is a safety net that normal play stays below; do not set loudness with it.
  Consumers: >=2 (Sfx, Music).
- **`Sfx`**, `autoload/sfx.gd`, confirmed
  Plays every sound effect from one polyphonic player on the SFX bus. Contract: `play(sound, pitch = 1.0, volume_db = 0.0)` with a key of `AudioBank.SFX` (`volume_db` adds to the `db` of the key), `note(sound, step, volume_db = 0.0)` on the `paint`, `ring` or `star` note ladder of `AudioTuning`, `warm_up()`, `silence()`, `missing()`. It connects to the Bus by itself and Game is its only direct caller, so a sound for a game event is a Bus handler here. Each paint ladder step adds `AudioTuning.PAINT_STEP_DB`; stop sounds that start in one `STOP_WINDOW_MS` play `STOP_VOICES` at most, each later one `STOP_EXTRA_DB` softer; the board sounds (swipe, thud, paint, repaint, glide, stops) add `AudioTuning.REPLAY_BOARD_DB` between `Bus.replay_started` and `Bus.replay_finished`. It is silent on the Dummy driver, `--audio-log` prints each play, and the `sfx` setting mutes its bus.
  Consumers: >=1 (Game calls `warm_up`, `missing` and `silence`); all other triggers come through Bus.
- **`Music`**, `autoload/music.gd`, confirmed
  The calm and tense music loops, with the beat clock, the fill filter, the duck and the defeat tape stop. Contract: `start()`, `stop()`, `set_tense(on)` (the change starts on the next beat of the clip that plays), `set_fill(ratio)` (low-pass cutoff from the painted share), `duck(db, seconds)`, `unduck(seconds)`, `tape_stop(seconds)`, `state() -> {playing, clip, bpm, cutoff_hz, beat}`; it emits `Bus.music_beat(index, tense)` and connects by itself to the Bus tension, session, ceremony, level, pause and setting signals. ## persistence

- **`Save`**, `autoload/save.gd`, confirmed
  Level progress, settings, the language choice and the theme choice in `user://save.cfg`. Contract: `record(level_id, stars, moves, time_ms) -> {new_best}` (each field keeps its better value; a result with no star stores nothing; an id that `LevelModes.is_level_id` refuses, such as `random`, stores nothing and pushes a warning), `best(level_id) -> {stars, best_moves, best_time_ms}`, `is_unlocked(index)` (level 0 always; level n when level n - 1 has one star or more in its normal or its `<id>_solo` record), `highest_unlocked()`, `setting(key)` and `set_setting(key, value)` for the bool keys of `DEFAULT_SETTINGS` (emits `Bus.setting_changed`), `language()` (the forced language of this run, else the stored choice, else `Strings.locale_for` of the device language), `set_language(code)` (the one entry point of a language change: it stores the choice, sets the Strings locale and emits `Bus.locale_changed`), `force_language(code)` (this run only, no write; for the harness), `theme()` (the forced theme of this run, else the stored choice, else the dark mode of the device), `set_theme(value)` (stores the choice and flushes at once), `force_theme(value)` (this run only, no write; for the harness), `use_path(path)`, `unlock_all()` (memory only), `flush()`. The `language` key is written only after the player chose one, so with no key the UI follows the device. The `theme` key sits next to `language` in `[settings]`, holds "light" or "dark", is not a `DEFAULT_SETTINGS` key and is written only after the player chose one, so with no key the game follows the device; `set_theme` and `force_theme` refuse a value outside `Palette.THEMES`, and each change of the `theme()` value, also at load and on `use_path`, emits `Bus.theme_changed`, not `setting_changed`. The `solo` setting is the wish of the player; [[PRIMITIVES#LevelModes]] decides the version. A one-block version keeps its own record under `<id>_solo`, so the best moves of the two versions never mix. Records use the level `id` as key, so a changed `id` in `levels_data.gd` loses its record; an unreadable file becomes `<name>.bad` and play continues with default data. Save listens to no Bus signal.
  Consumers: >=12 (Feel, Game, Harness, Music, Sfx, ui_lab, home_screen, level_card, level_select_screen, ToggleRow, LanguageRow, ThemeRow).

## dev tooling

- **`Harness`**, `autoload/harness.gd`, confirmed
  Scripted runs from the command line: screenshots, scripted play, logs and a watchdog. Contract: arguments after `--` as `--key=value` or `--flag` (read in `_ready`, `_apply_setup` and `_plan`; the header comment of the file lists the language, mode, random, replay, theme and tap flags with their marks); `active()`, `has_arg(key)`, `arg(key, fallback)`, `shot(name)`, `mark(event)` (prints `HARNESS MARK`, takes the `--shot-on` shot, obeys `--quit-at`; once the run ends, for example by `--quit-at` at that event, no tap and no theme switch starts at that event), `finish(code)` (prints the collected failures, and quits with 1 when `code` is 0 and a failure exists). It does nothing without arguments, stays silent in a `--script` tool run, reads the game only through the Game API and the Bus, and blocks real input during scripted play; only while a harness tap is in flight, the emulated mouse events of its touch pass, so the tap reaches the buttons.   Consumers: >=5 (Game, Music, Sfx, board_lab, ui_lab).
